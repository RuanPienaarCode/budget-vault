Subcategories

One budget for Car, with fuel, services and tolls visible underneath it. An optional label under a category that shows where the money went and never changes a figure.

Problem statement

The finest thing a transaction can say about itself is its category. A household that wants to know how much of Car went on fuel has two options today, and neither works.

  • Make more categories. Fuel, Services and Tolls each need their own note and their own line in every period's budget. The household now budgets three figures it only wanted to see, and the Car total it started with no longer exists anywhere: the Dashboard has no spending roll-up by group.
  • Write it in the Note. Search finds it, but it cannot be filtered, summed or picked from a list, and two spellings count as two things.

The cost of leaving it: the question "what is this category made of" stays unanswered inside the plugin, and people who need it either leave or keep a second record elsewhere.

Goals

  1. A transaction can carry one optional subcategory under its category, set from the Transactions table and the Add dialog.
  2. For every category and window, its subcategories plus the transactions that have none add up to exactly the category's own figure, refunds included. A test holds this on both household seeds.
  3. No figure that exists in 1.60 changes. The two pinned figure ledgers pass without an edit.
  4. A transaction file with no subcategory is byte-for-byte unchanged after load and save.
  5. Someone who imports statements sets a subcategory once per merchant; a rule fills it in on every later import.
  6. A vault that never uses subcategories sees no new control anywhere.

Users and access model

Budget Vault has no accounts, no sign-in and no server. Everyone who can open the vault can use every part of the plugin, and that does not change.

WhoHow they meet the feature
Someone who types entries inPicks a subcategory in the Add dialog or in the table.
Someone who imports statementsSets it once on Transactions; a rule learns the pair and applies it on later imports.
Someone on a phoneThe same controls. The subcategory is a second line inside the existing category cell of the transaction card.
Someone who never wants itSees nothing new. No control appears until the open book has a subcategory.

User stories

Tags are the four build slices. All four ship to the store as one version.

Setting up the names

  • Slice 1As a budgeter, I want to open a Subcategories dialog for a category from the Budget page so that I can add the first names before any dropdown exists.
  • Slice 1As a budgeter, I want to remove a name from the list without my old transactions changing so that tidying the list is safe.
  • Slice 1As a budgeter, I want to pick "＋ New subcategory…" at the bottom of the dropdown so that I can add a name without leaving the row I am on.

Labelling transactions

  • Slice 1As a budgeter, I want a subcategory dropdown under the category in the Transactions table so that I can label a row where I already categorise it.
  • Slice 1As a budgeter, I want a subcategory dropdown under Category in the Add dialog so that a new entry is complete in one step.
  • Slice 1As a budgeter, I want the subcategory cleared when I change a row's category so that a row never claims a subcategory of the wrong category.
  • Slice 1As a budgeter, I want each part of a split to carry its own subcategory so that one bank line can be divided all the way down.
  • Slice 1As someone who does not use subcategories, I want no new controls and no change to my files so that the update costs me nothing.

Finding them again

  • Slice 1As a budgeter, I want to filter Transactions by subcategory, including "No subcategory", so that I can see exactly the rows behind a figure.
  • Slice 1As a budgeter, I want search to match subcategory names so that typing "fuel" finds the rows labelled Fuel.

Importing

  • Slice 2As someone who imports statements, I want a rule to set the subcategory along with the category so that I do not pick it by hand on every row, every month.
  • Slice 2As someone who imports statements, I want the pair learned when I save a row with both set so that I never edit the rules file myself.
  • Slice 2As someone who imports statements, I want the import review to show the subcategory a rule chose so that I can see what will be saved.

Seeing the breakdown

  • Slice 3As a budgeter, I want a category in "Where it went" to expand into its subcategories with amounts so that I can see what the category is made of.
  • Slice 3As a budgeter, I want to click a subcategory and land on Transactions filtered to it so that I can check the rows.
  • Slice 3As a budgeter, I want an "All transactions" row in the expansion so that I can still open the whole category.

Taking the data out

  • Slice 4As a budgeter, I want the transaction exports to include the subcategory so that the detail survives outside the plugin.

Testing decisions

Seams under test

SeamWhat it provesPrior art to mirror

Per-category figuresSubcategories plus "No subcategory" add up to the category's figure, refunds included, on both household seeds.summary-conservation, dash-donut-printed-figures
Rendered pages through the view harnessThe dropdowns, filter, Budget dialog and Dashboard expansion appear only when used. The two pinned figure ledgers stay unchanged for the existing seeds.figures-ledger, views-render, i18n-render

Rules and export are pure functions and are tested where they already are: rules-csv-roundtrip, exporter and export-preview-equals-written.

What a good test looks like here

It drives a file or a page the way a household would and asserts what comes back out: the bytes written, the figure printed, the control on screen. It never reaches into a module's internals.

Modules under test

  • Slice 1 carries the critical path: the file round trip and the adds-up rule.
  • Slice 2: rule matching and learning, including a rule with a blank subcategory.
  • Slice 3: the rendered Dashboard expansion against the same figures as slice 1.
  • Slice 4: the written export equals the previewed one, with and without the column.
Contract before code
Each slice agrees its function signatures, return shapes, error cases and named test cases before the first failing test is written.

Phased delivery plan

Four slices in order. Each is deployed to the Pienaar Vault when it lands. The store release is one version, cut once all four are in.

Slice 1

Core

The column, the list on the category note, the Subcategories dialog, the dropdowns in the table and the Add dialog, the filter and search.

Unlocks

Usable on its own by anyone typing entries in. Everything else builds on it.

Accepted when

  • A file with no subcategory is unchanged after load and save.
  • The column is read directly after Note, after Split, and after an unknown column.
  • The adds-up test passes on both household seeds.
  • Changing a category clears the subcategory.
  • Both pinned figure ledgers pass unedited.
  • No new control shows in a book with no subcategory.
Slice 2

Import rules

A rule can set a subcategory and learns it from a save on Transactions. The import review shows it as text.

Unlocks

The feature is worth having for people who import statements.

Accepted when

  • A rules file with two columns loads and saves unchanged.
  • A rule with a blank subcategory sets the category alone.
  • Saving a row with both set teaches the pair, and the next import applies both.
Slice 3

Dashboard expansion

A category in "Where it went" expands into its subcategories, with an "All transactions" row.

Unlocks

The breakdown is visible without filtering.

Accepted when

  • The expanded amounts add up to the category's printed figure.
  • A category with no subcategorised spending in the window opens Transactions as before.
  • The collapsed "Other" row is unchanged.
  • Clicking a subcategory opens Transactions filtered to it.
Slice 4

Export

A Subcategory column in the CSV, Markdown and XLSX transaction exports and the report's JSON.

Unlocks

The store release.

Accepted when

  • The column is present when the book uses subcategories and absent when it does not.
  • The written file equals the preview.
  • The PDF is unchanged.

Data model sketch

Type / group            (Settings: built-in types plus custom groups)
   └── Category         (one note per category; budgets are set here)
          │  subcategories: "Fuel, Services, Tolls"      ← the offered names, in order
          │
          └── Subcategory            (a name; belongs to exactly one category)
                 ▲
                 │ 0 or 1
Transaction ─────┘      Date | Description | Category | Amount | Excluded | Note | [Split] | … | [Subcategory]
                        the column exists in a month's file only once a row in it uses one

Categorisation rule     pattern | category | [subcategory]
  • A transaction has at most one subcategory, and only if it has a category.
  • A split part is a transaction and follows the same rule.
  • A budget row points at a category and nothing below it.
  • A name on a transaction that is missing from the category's list is still a subcategory of that category.

Integrations

None. The feature makes no network request and adds no dependency. It reads and writes three kinds of file the plugin already owns: the month's transaction file, the category note, and the categorisation rules file.

An older build on another device
A device still running 1.60 or earlier keeps the column intact but does not understand it. Changing a row's category there leaves the old subcategory on the row. The newer build then shows it as a name in use under the new category instead of dropping it.

Success metrics

  • The adds-up test passes on both household seeds in every slice.
  • Both pinned figure ledgers pass with no edit across all four slices.
  • The byte-for-byte file test passes for a transaction file and a rules file that use no subcategory.
  • Ruan labels one month of a real category in the Pienaar Vault after slice 1, on a computer and on an iPhone, with no change to any figure on the Dashboard.
  • After slice 2, a second import of the same merchants needs no subcategory picked by hand.
  • No issue reporting a changed figure or a rewritten file in the 30 days after the store release.
